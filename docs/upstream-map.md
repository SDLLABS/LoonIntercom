## Target silicon evidence

Espressif's [ESP32-P4 Series datasheet, section 4.2.1](https://www.espressif.com/sites/default/files/documentation/esp32-p4_datasheet_en.pdf) documents a Baseline H.264 hardware encoder with maximum 1080p30 performance for YUV420 input, plus MIPI-CSI and an ISP. This is an established SoC capability, not an OpenChime port or proof that a selected board, sensor/driver, PSRAM, NOR, Ethernet/PoE and audio combination works. WP2 validates those board paths and capture/encode; WP3 evaluates complete streams, RTSP/WebRTC, Opus/AEC, latency and memory/CPU/network budgets.

## Provenance and license rules

The current SDLLABS `main` remains at the Aikos commit above; this branch adds handoff/architecture material and WP1 docs. Existing Aikos bell and screen code stays in place. OpenChime is [MIT licensed](https://github.com/exddc/openchime/blob/8085381252216dccae1ad18aaa766daee0c03c6c/LICENSE); no code was copied for WP1. A future port must record upstream repository, commit, source path, copied/adapted files, modification summary, and applicable copyright/license notices in the change and retain the MIT notice where required. Third-party code nested inside OpenChime needs its own license audit. The existing screen driver has separate [license information](https://github.com/aikos-home/intercom/blob/77b56da677b08da73ba137dddba78e8834585f59/firmware/screen/components/lilygo_t5_47_plus/LICENSE).

## Baseline reconciliation

The inherited `docs/architecture.md` says the ring goes to HA first and rules out cameras. Those statements describe an earlier Aikos product concept. The current bell implementation sends a direct RoomKey packet independently of HA, and SDLLABS v2 adds a separate P4 camera subsystem while leaving the bell path intact. Do not rewrite the inherited historical document as evidence of v2 implementation. See [architecture v2](architecture-v2.md) and its ADRs for the adopted direction.
